O Docker Content Trust, também conhecido como DCT é, em sua essência, utilizado para permitir que o autor de uma imagem possa assiná-la, garantindo que a tag seja realmente íntegra e rastreável. Muitas empresas utilizam este recurso dentro de pipelines, para garantir que o Docker não realize o pull de uma imagem feita por terceiros, no lugar de uma imagem oficial. Isso possibilita que um Dockerfile com uma imagem base (utilizada na cláusula FROM) diferente da esperada/segura, seja imediatamente interrompido em seu build, garantindo confiabilidade.

```bash
# Realizando a criação de um registry local para testes
docker run -d -p 5000:5000 --name registry registry:3

# Realizando a instalação do Notary (projeto utilizado para realizar assinaturas de tags)
cd /tmp
git clone https://github.com/notaryproject/notary.git && cd notary
docker-compose up -d
```

```ad-important
Importante ressaltar que o Notary foi usado para fins de exemplificação. Qualquer serviço dessa natureza, que seja devidamente confiável, poderá ser utilizado para este fim, seguindo os passos expressos em documentação oficial do Docker sobre o recurso de DCT.
```

A aplicação do Notary irá realizar o deploy de 4 containers para o serviço de assinaturas:

- notary_server
- notary_signer
- notary_mysql_1
- registry:3

Agora, é necessário exportar uma variável para o DCT, conforme mostrado abaixo:

```bash
# É necessário apontar o valor da variável para o container com a imagem do notary_server, que possui um certificado válido para HTTPS (4443)
export DOCKER_CONTENT_TRUST=https://localhost:4443
```


Para início dos testes, o primeiro passo é realizar o push de uma imagem com tag não assinada, e verificar seu comportamento (dockerd/containerd):

```bash
# ESTRUTURA BASE:
# - "locahost:5000": registry
# - "alpine": repository
# - "unsigned": tag
docker tag alpine:latest localhost:5000/alpine:unsigned

# Realizar o push da docker image
docker push localhost:5000/alpine:unsigned
```

Isto realiza o envio da imagem para o registry local, previamente configurado nos passos anteriores. Agora, realizaremos o delete da imagem local, e também o export da variável específica para forçar o DCT a atuar nos próximos pulls e pushes:

```bash
# Realizando o delete da imagem no host local
docker image rm localhost:5000/alpine:unsigned

# Export da variável de ativação de validação
export DOCKER_CONTENT_TRUST=1
```

A partir deste export, apenas imagens confiáveis e aprovadas pelo Notary, poderão ser obtidas com o comando `pull`. A imagem anteriormente enviada ao registry sem assinatura, não poderá ser obtida novamente, devido a falta da assinatura solicitada pelo Notary para validação. Isso pode ser comprovado na saída do comando, como visto abaixo:

```bash
docker pull localhost:5000/alpine:unsigned
```

> Output: _Error: remote trust data does not exists for localhost:5000/alpine localhost:4443 does not have trust data for localhost:5000/alpine_

Para confirmar que a operação realmente teve falha, a nível de sistema operacional, pode-se verificar com o comando abaixo, que obtém como retorno o resultado "1", indicando a falha ocorrida:

```bash
echo $?
```

## Assinando imagens com o DCT

```bash
# Gerando uma key (assimétrica (public/private)) para assinaturas com DCT, com nomenclatura de exemplo
docker trust key generate payment-service-team 

# Verificando sucesso da geração da public key
cat payment-service-team.pub

# Verificando sucesso da geração e load da private key
cd ~/.docker/trust/
cat 2378i4ohytrfo8327yrtfhcbnq8oyot273485fhc.key

# Atrelando a chave gerada ao repositório da docker image desejada (alpine:unsigned)
# ESTRUTURA: docker trust signer add OPTIONS NAME REPOSITORY [REPOSITORY...]
cd /tmp
docker trust signer add --key payment-service-team.pub payment-service-team localhost:5000/alpine

# Inspecionando a docker image, para verificar dados de assinaturas.
# IMPORTANTE: A chave "SignedTags" estará vazia, no momento. Porém, as assinaturas serão realizadas no momento do pull automaticamente.
docker trust inspect localhost:5000/alpine

# Realizando o novo push da docker image
docker tag alpine:latest localhost:5000/alpine:signed
docker push localhost:5000/alpine:signed

# Neste momento, a chave "SignedTags" estará com três chaves preenchidas (SignedTag, Digest, Signers)
docker trust inspect localhost:5000/alpine

# Realizando o novo pull da docker image assinada, com sucesso
docker pull localhost:5000/alpine:signed
```

```ad-warning
**Lembre-se de guardar bem a root key que é criada durante o processo de adição do DCT signer!** Caso esta seja perdida, o acesso às operações de pull das imagens é **inviabilizado**.
```


## Assinando imagens manualmente com o DCT

```bash
# Assinando a imagem manualmente
docker trust sign localhost:5000/alpine:unsigned

# Realizando o push
docker push localhost:5000/alpine:unsigned

# Verificando assinatura da tag
docker trust inspect localhost:5000/alpine
```

## Comportamento de assinaturas em um CI (Continuous Integration)

```bash
# Atribuindo tag
docker tag alpine:latest localhost:5000/alpine:dockerfile

# Realizando unset de variável do DCT
unset DOCKER_CONTENT_TRUST

# Realizando push (docker image sem assinatura)
docker push localhost:5000/alpine:dockerfile

# Realizando export da variável do DCT
export DOCKER_CONTENT_TRUST=1

# Limpando o docker image local cache
docker image rm localhost:5000/alpine:dockerfile

# Criando um Dockerfile
mkdir ./demo
cat <<EOF > ./demo/Dockerfile 
FROM localhost:5000/alpine:dockerfile 
RUN apk add --no-cache curl
EOF

# Realizando o build do Dockerfile (com erro de assinatura faltante)
cd demo
docker build -t alpine:demo -f Dockerfile .

# Verificando estado de erro (output = 1)
echo $?

# Modificando Dockerfile para imagem assinada
cat <<EOF > Dockerfile 
FROM localhost:5000/alpine:signed 
RUN apk add --no-cache curl
EOF

# Realizando o build do Dockerfile (com imagem assinada previamente)
docker build -t alpine:demo -f Dockerfile .

# Verificando estado de sucesso (output = 0)
echo $?
```
