## Manuseando secrets

```ad-warning
Para a prática destes passos, é necessário que exista um cluster de docker swarm em execução!
```

```bash
# Desabilitando o DCT
unset DOCKER_CONTENT_TRUST_SERVER
unset DOCKER_CONTENT_TRUST

# Criando um secret com STDIN "-" (o sinal de "-" captura a saída do comando anterior, e a trata como entrada pelo piping)
echo "demo" | docker secret create demo -

# Verificando a criação do secret
docker secret ls

# Criando um serviço utilizando o secret criado
docker service create --secret demo --name nginx nginx

# Verificando o service
docker service ps nginx

# Acessando o node onde o service está contido
ssh swarm-1@192.168.1.123

# Acessando o container que o service está contido
docker exec -it <container_id> sh

# Verificando a existência do secret e seu conteúdo plaintext no container host do service
cd /run && ls --color
cd secrets && ls demo
cat demo
```

## Realizando o uso de Docker Secrets em um Docker Compose

```bash
# Criando docker-compose.yml (referenciado a seguir)
mkdir -p ./wordpress
cd wordpress
touch docker-compose.yml

# Gerando password pseudo-randômico com openssl rand
openssl rand -base64 20 > db_wordpress.txt
openssl rand -base64 20 > db_root.txt
```

- Criando secrets:

```ad-important
Importante destacar que as configurações de labels do cluster Swarm já foram previamente configuradas neste exemplo, com o comando abaixo:

```bash
docker node update --label-add db=true <node_id>
```

```yaml
services:
  db:
    image: mysql:5.7
    volumes:
      - db_data:/var/lib/mysql
    environment:
      # Método de "*_FILE: path" suportado pela imagem do MySQL
      MYSQL_ROOT_PASSWORD_FILE: /run/secrets/db_root
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wordpress
      MYSQL_PASSWORD_FILE: /run/secrets/db_wordpress
    networks:
      - wordpress-overlay
    deploy:
      placement:
        constraints:
          - "node.labels.db==true"
      replicas: 1
    secrets:
      - db_wordpress
      - db_root

  frontend:
    image: wordpress:latest
    volumes:
      - wordpress_data:/var/www/html
    ports:
      - "80:80"
    environment:
      # Método de "*_FILE: path" suportado pela imagem do MySQL
      WORDPRESS_DB_HOST: db:3306
      WORDPRESS_DB_USER: wordpress
      WORDPRESS_DB_PASSWORD_FILE: /run/secrets/db_wordpress
      WORDPRESS_DB_NAME: wordpress
    networks:
      - wordpress-overlay
    deploy:
      replicas: 5
    secrets:
      - db_wordpress

secrets:
  db_root:
    file: db_root.txt
  db_wordpress:
    file: db_wordpress.txt

volumes:
  db_data:
  wordpress_data:
    driver_opts:
      type: "nfs"
      o: "addr=172.89.0.20,rw,nolock"
      device: ":/srv/wordpress"
      
networks:
  wordpress-overlay:
    driver: overlay
    attachable: true
    name: wordpress-overlay
    driver_opts:
      encrypted: "true"
```

```bash
# Aplicando a stack
docker stack deploy -c docker-compose.yml wordpress_secrets


# Verificando o service
docker service ls
```

A partir deste momento, a aplicação do Wordpress estará acessível no browser através da URL correta com o IP do node que possui o service em execução.
