## Seccomp


``` bash
docker run -it --security-opt seccomp=nochmod alpine sh
```

```ad-info
Este tipo de controle de permissões, permite que algumas syscalls sejam bloqueadas em containers, seguindo um arquivo de configuração padronizado pelo projeto _Moby_, também desenvolvido pelos mantenedores do Docker.

O arquivo pode ser encontrado no repositório do [projeto Moby](https://raw.githubusercontent.com/moby/moby/85eaf23bf46b12827273ab2ff523c753117dbdc7/profiles/seccomp/default.json "Projeto Moby"), no GitHub. 
```

O próprio arquivo possui várias syscalls, que por sua vez podem ser manuseadas pelo arquivo, de forma a controlar o comportamento do container com restrições de operações a nível de kernel, proveniente do próprio host.

Vale mencionar que o Seccomp é uma implementação do princípio do **Privilégio Mínimo**. O perfil padrão do Docker bloqueia cerca de 44 syscalls de mais de 300 disponíveis, protegendo o kernel do host contra ataques de escalação de privilégio.

Uma prévia do arquivo se encontra logo abaixo com a sessão de syscalls disponível separadamente em lista.

## Capabilities: o método mais estável e mais usado

Capabilities são um conjunto de recursos do kernel linux do host, que podem ser manipulados dentro dos cgroups e namespaces dos containers, para privação ou adição de permissões ao sistema operacional do container, que compartilha o mesmo kernel. Estes recursos podem ser listados facilmente pelo manual de comandos do Linux, com o comando abaixo:

```bash
man -k capabilities
```

Para verificar estes recursos dentro dos containers, precisamos de um utilitário específico, chamado (em distribuições Debian-like) de _libcap-ng-utils_, que pode ser facilmente instalada no sistema com o comando abaixo:

```bash
sudo apt install libcap-ng-utils -y
```

Este utilitário permite catalogar as diversas capabilities de um processo no host (incluindo processos de containers em execução), com o seguinte comando:

```bash
sudo pscap | grep <PID>
```

Para manipular estas capabilities, temos os comandos abaixo, com os devidos parâmetros de exemplo:

```bash
# Lista os containers docker em execução, com informações primárias (pid, name, image, uptime, etc.)
docker ps

# Lista os processos de um container docker específico no host
docker container top <container_id>

# Lista os processos do host e, consequentemente dos containers docker localizados no host, por meio do dockerd/containerd (daemon do Docker)
ps aux | grep <container_process_pid>

# Lista as capabilities do container como processo
sudo pscap | grep <pid>

# Executa o container docker com a remoção de uma capability
docker run -d --cap-drop chown,kill alpine
```

```ad-important
Como boa prática, é recomendado para tuning de segurança, q os seguintes passos abaixo sejam seguidos:

```bash
# Realize apenas a inserção das capabilities 
# realmente necessárias para o container, com análise
# prévia das opções previstas no comando ((man -k capabilities))
docker run -d --cap-drop ALL --cap-add NET_BIND_SERVICE,chown alpine
```

```ad-note
Caso o container possua o pacote _libcap-ng-utils_ (ou equivalente), existe a possibilidade de realizar a verificação da situação das capabilities do próprio container, com o comando abaixo:

```bash
capsh --print
```
