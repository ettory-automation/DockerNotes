## O que é o chroot?

O _chroot_ é uma ferramenta/recurso do Linux, que realiza o isolamento de um diretório dentro do sistema operacional host. Ou seja, ele cria um ecossistema totalmente independente dentro do sistema operacional em que se encontra.

Para iniciarmos a compreensão de maneira sucinta do recurso _chroot_ no linux, primeiramente criaremos um diretório para a execução das práticas:

```shell
mkdir ./chroot
```

Quando for assumido o diretório denominado por "chroot", será criada uma nova estrutura de pastas pela ferramenta _chroot_, o que fará com que a raiz do sistema seja reconhecida como sendo o diretório assumido. Prosseguindo com a prática, iremos executar o bash dentro do diretório proposto.

```shell
sudo chroot ./chroot bash
```

O seguinte erro aparece quando executada esta ação:

_chroot: failed to run command 'bash': No such file or directory_

Como pode-se notar, para realizar a ação, devemos configurar o bash para tal. Então seguiremos para esta configuração revisando conceitos base do sistema:


1. Executando o comando a seguir, será possível verificar todas as _libraries_ utilizadas pelo _bash_: 

```shell
ldd /bin/bash
```

2. Neste momento, por vias teóricas, para executar o bash no diretório escolhido, teriam de ser realizadas as cópias de todas as _libraries_ que são utilizadas pelo _bash_, e o binário da ferramenta _bash_. Porém, também deve-se criar a mesma estrutura de diretórios existentes no _FHS_ (_Filesystem Hierarchy Standard_), que é o padrão que determina a estrutura de diretórios e arquivos em sistemas operacionais _Unix-like_. Ou seja, os seguintes passos devem ser executados em ordem:

* Criar os diretórios baseados na estrutura definida pelo _FHS_:

```shell
cd ./chroot
mkdir bin
mkdir lib
mkdir lib64
```

 * Copiar as _libraries_ necessárias para os diretórios internos ./chroot/lib e ./chroot/lib64:

```shell
sudo cp /lib/x86_64-linux-gnu/libtinfo.so.6 lib/
sudo cp /lib/x86_64-linux-gnu/libc.so.6 lib/
sudo cp /lib64/ld-linux-x86-64.so.2 lib64/
```

* Copiar binário do bash para a pasta ./chroot/bin:

```shell
sudo cp /bin/bash bin/
```

* Verificar conteúdos do diretório ./chroot:

```shell
ls **
```

3. Agora, com o binário e as _libraries_ nos locais descritos pelo _FHS_, podemos finalmente executar o _chroot_ no diretório escolhido, realizando os comandos abaixo:

```shell
cd ..
sudo chroot ./chroot bash
```


Neste momento, foi realizado um isolamento de bash no diretório selecionado, de forma que qualquer comando diferente de "bash" não será reconhecido. Testes podem ser realizados com comandos como os abaixo:

Gera um erro de inexistência no isolamento:

```shell
ls
```

Gera sucesso pelas _libs_ adicionadas do bash no isolamento:

```shell
bash --version
```

4. Devemos adicionar o comando _ps_ dentro do nosso diretório chroot. O procedimento é o mesmo que havia sido realizado para o _bash_:

```shell
which ps
for i in $(ldd /usr/bin/ps | cut -d " " -f 3); do sudo cp $i lib/; done
sudo cp /lib64/ld-linux-x86-64.so.2 lib64/
sudo cp /usr/bin/ps bin
```

Observe que este processo deve ser realizado também para as ferramentas _ls_ e _mount_. Caso contrário, o comando _ps_ **não ficará disponível!**

* Montando /proc do sistema host no diretório chroot:

```shell
sudo mount -t proc proc proc
```

* Acessando o chroot novamente para executar o comando _ps_:

```shell
sudo chroot .
```


## Conclusão

Até o momento, conseguimos realizar uma parte inicial do isolamento de recursos, um dos fundamentos básicos de containers.
