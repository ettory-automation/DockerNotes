## Dividindo a arquitetura do Docker

| Client      | Docker Host   | Registry |
| ----------- | ------------- | -------- |
| docker ps   | Docker daemon | nginx    |
| docker pull | Images        | centOS   |
| docker run  | Containers    | Redis    |

Quando falamos sobre Docker, devemos separar os componentes em três categorias primárias: Client, Host e Registry.

* Docker Client: É a origem da conexão, basicamente é o "CLI Toolkit" do Docker (ex.: _docker ps_; _docker pull_; _docker run_). Quando o Docker é instalado no host, ele instala o _Docker Client_ e o _Docker Host_, onde ambos são componentes diferentes, mesmo que similares. Importante salientar que o _Docker Client_ pode controlar diversos hosts, dependendo apenas da existência de roteamento e conexão na porta necessária. Ou seja, o _Docker Client_ envia a requisição para o _Docker Host_, e este a executa.
* Docker Host: Executa a ação do _Docker Client_, por meio das requisições recebidas por ele. Por meio de seu _daemon_ (processo _docker_ em segundo plano), executa ações como _run_ de _images_, _download_ de _images_, _create_ de _containers_ e suas configurações, etc..
* Registry: Após realizar as ações de _build_ e _push_ de _images_, estas vêm para este componente, o _Registry_. Alguns exemplos básicos de _Registries_ seriam _Jfrog_, _Nexus_, _ECR_, _Docker Hub_ (default), entre outros. Porém, existem Registries em duas categorias:
	* Public Registry: _Docker Hub_, _Public ECR_, etc..
	* Private Registry: Muito utilizado para armazenar as _images_ dos _containers_ que compõem a infraestrutura empresarial, localmente.
