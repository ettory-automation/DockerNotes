**O principal fator que leva ao uso de containers** com _Docker_, é a **facilidade de gerenciamento de variáveis, versionamento de libraries, facilidade de tuning (otimização), gerenciamento de arquivos de configuração**, entre muitos outros.

Um exemplo bom para o gerenciamento de variáveis seria o gerenciamento das _Secrets_ (variáveis envoltas no contexto de cybersecurity como, por exemplo, senhas de bancos de dados)

## Como Utilizar os Recursos do Docker?

* ***Princípio da Imutabilidade***:
	* ***Docker Image*** (Artefato/Objeto):
		* App
		* Variáveis
		* Libraries
		* Tuning
		* Config


```ad-note
**A partir da Docker Image, é criado o container. Porém, o container é não possui ligação direta alguma com a Docker Image.** Isso significa que o **container, quando alterado, não modifica a imagem**, uma vez que a _imagem é read only!_ Enquanto isso, o _container tem propriedades de escrita (write)_.
```

Possuindo uma Docker Image, é possível realizar sua distribuição e deployment em quaisquer ambientes (ex.: (AWS, Azure, GCP, DO, OCI) + Container Engine/Docker ou ambientes on-premises)
