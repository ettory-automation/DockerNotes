## O que são cgroups?

Os cgroups são recursos do Linux que podem delimitar quantidades de recursos computacionais de hardware para determinados grupos de processos.

Para início da prática, iremos criar um diretório para realizar as operações:

```shell
mkdir ~/cgroups
```

Antes de prosseguirmos, devemos ir ao diretório localizado em /sys/cgroup para verificarmos o que é o comando _cgroup_ em si.

Acessando o diretório /sys/cgroup:

```shell
cd /sys/cgroup
```

Verificando o conteúdo desde diretório, veremos todos os componentes aos quais o _cgroup_ realiza o controle de consumo de recursos computacionais. São eles:

* blkio
* cpu
* cpuacct
* cpu,cpuacct
* cpuset
* devices
* freezer
* hugetlb
* memory
* net_cls
* net_cls,net_prio
* net_prio
* perf_event
* pids
* systemd

Sendo que, destes listados acima, os mais utilizados são _memory_ e _cpu_. Para demonstrar todas as possibilidades de controle para estes elementos listados, será utilizado o recurso localizado em _/sys/cgroup/cpu_.

```shell
ls /sys/cgroup/cpu
```

Verificando o conteúdo deste diretório, veremos todas as configurações default presentes para delimitar o consumo de recursos de CPU no sistema operacional. São elas:

* cgroup.clone_children
* cgroup.event_control
* cgroup.procs
* cgroup.sane_behavior
* cpuacct.stat
* cpuacct.usage
* cpuacct.usage_percpu
* cpu.cfs_period_us
* cpu.cfs_quota_us
* cpu.rt_period_us
* cpu.rt_runtime_us
* cpu.shares
* cpu.stat
* notify_on_release
* release_agent
* tasks

Onde o _tasks_ possui os processos que as demais opções listadas realizarão a aplicação de limites (controle).

Caso seja criado um diretório manualmente dentro do caminho _/sys/cgroup/*_ , este será populado automaticamente com as configurações default do cgroup para aquele recurso selecionado. Exemplo com os recursos de CPU:

```shell
mkdir /sys/cgroup/cpu/demo
cd /sys/cgroup/cpu/demo
ls . -l
```

Output:

* cgroup.clone_children
* cgroup.event_control
* cgroup.procs
* cgroup.sane_behavior
* cpuacct.stat
* cpuacct.usage
* cpuacct.usage_percpu
* cpu.cfs_period_us
* cpu.cfs_quota_us
* cpu.rt_period_us
* cpu.rt_runtime_us
* cpu.shares
* cpu.stat
* notify_on_release
* release_agent
* tasks

Neste momento, estamos aptos a iniciar processos, e adicionar os processos dentro deste cgroup (ex.: demo).

Para facilitar a exemplificação, serão iniciados alguns processos que consomem uma alta quantidade de CPU, e estes processos serão adicionados à este cgroup, para que assim eles dividam a quantidade de CPU entre si.

Iniciando um processo com o comando _dd_ para consumo de CPU:

```shell
dd if=/dev/zero of=/dev/null bs=1M &
```

Este comando inicia uma gravação do conteúdo de _/dev/zero_, que possui valor nulo, para _/dev/null_, que também possui valor nulo. Isto será feito no intervalo de 1 megabyte, e será colocado em background com o uso do operador _"&"_.

Este comando será executado duas vezes, para que seja atingido o valor de consumo máximo de dois cores de CPU (quantidade máxima de hardware para demonstração), ou seja, 100% de consumo em cada core.

Caso seja iniciado um terceiro processo que consuma CPU excessivamente, um balanceamento de carga entre os cores irá ocorrer, para que fique aproximadamente 55~60% de consumo para cada processo, totalizando em média 200% em somatória, o que atinge a capacidade máxima de consumo possível em duas vCPUs.

Iremos agora verificar o conteúdo de _/sys/cgroup/cpu/demo/tasks_, e constatar que o mesmo se encontra ainda vazio. A próxima etapa será adicionarmos ao _cgroup "demo"_, os processos inicializados anteriormente com a ferramenta _dd_. Para realizarmos isto, devemos pegar os PIDs dos processos inicializados, e iremos transmitir os mesmos para dentro do diretório _/sys/cgroup/cpu/demo/tasks_, com o comando abaixo:

```shell
echo 2334 >> /sys/cgroup/cpu/demo/tasks
echo 2337 >> /sys/cgroup/cpu/demo/tasks
```

Isto faz com que cada um dos processos adicionados, compartilhem entre si o mesmo cgroup, tornando-os completamente isolados do sistema host e os limites padrões do sistema localizados em _/sys/cgroup/cpu_.


```ad-note
Os dois processos que foram isolados no cgroup demonstrado, estão dividindo o consumo entre si em aproximadamente 50~50%, ou seja, estão ambos consumindo apenas 1 vCPU. Enquanto isso, o terceiro processo da lista está fora deste cgroup isolado, e está consumindo de forma completamente avulsa, 100% de 1 vCPU.
```
