A cláusula _ENTRYPOINT_ muitas vezes é confundida com a funcionalidade da cláusula _CMD_. Porém existem algumas diferenças marcantes entre essas duas funcionalidades:

1. A cláusula _CMD_ se trata dos comandos que serão executados durante a execução do _docker run_. Esta permite sobrescrição
2. A cláusula _ENTRYPOINT_ se trata do comando que será executado indiretamente. Diferentemente do _CMD_, a cláusula _ENTRYPOINT_ **não permite sobrescrição**.

Aplicação e Dockerfile de exemplo:

```javascript
const http = require('http');
const hostname = '0.0.0.0';
const port = process.env.PORT;
const version = process.env.VERSION;
const server = http.createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/plain');
  res.end('Hello World');
});

server.listen(port, hostname, () => {
  console.log(`Server running at http://${hostname}:${port}/ and version ${version}`);
});

process.on('SIGINT', function() {
    process.exit();
});
```

```Dockerfile
FROM node:alpine3.21

WORKDIR /var/nodeapp
COPY app.js .

USER node

# Define comando padrão (sobrescrevível)
CMD ["node", "app.js"]
```

Execução normal:

```bash
docker build -t nodeapp:cmd -f Dockerfile.cmd .
docker run -d -p 3000:3000 nodeapp:cmd
```

Sobrescrição com _CMD_:

```bash
docker run nodeapp:cmd node -v
```

O resultado disto será a impressão da versão do Node.js. O _CMD_ foi **substituído** por _node -v_.

Já com o _ENTRYPOINT_ temos o seguinte resultado:

```Dockerfile
FROM node:alpine3.21

WORKDIR /var/nodeapp
COPY app.js .

USER node

# Define comando fixo (não sobrescrevível)
ENTRYPOINT ["node", "app.js"]
```

Execução normal:

```bash
docker build -t nodeapp:entrypoint -f Dockerfile.entrypoint .
docker run -d -p 3000:3000 nodeapp:entrypoint
```

Onde o servidor roda normalmente em **[http://localhost:3000]**

Tentativa de sobrescrição:

```bash
docker run nodeapp:entrypoint node -v
```

Na tentativa de sobrescrição, percebe-se uma falha, pois o Docker ainda executa:

```bash
node app.js node -v
```

Isso significa que o _ENTRYPOINT_ **não é substituído**. Apenas recebe a nova entrada como argumento adicional.

Em resumo, a cláusula _CMD_ é vista como um parâmetro para o comando atribuído na cláusula _ENTRYPOINT_.

Para que seja sobrescrito no momento da execução do _docker run_, deve-se realizar o seguinte comando na inicialização:

```bash
#Exemplo com Docker Image do Terraform
docker run --entrypoint "" -it hashicorp/terraform sh

#Comando oficial puxando entrypoint como /bin/terraform
docker run hashicorp/terraform <arg>
```
