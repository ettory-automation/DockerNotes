De mesma forma como na injeção de variáveis de ambiente no momento da execução do container, podemos utilizar argumentos no momento do _build_ da imagem, para realizar este tipo de efeito no container.

Código da aplicação de exemplo:

```javascript
const http = require('http');
const hostname = '0.0.0.0';
const port = process.env.PORT;
const version = process.env.VERSION;
const server = http.createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/plain');
  res.end('Hello World');
});

server.listen(port, hostname, () => {
  console.log(`Server running at http://${hostname}:${port}/ and version ${version}`);
});

process.on('SIGINT', function() {
    process.exit();
});
```

O funcionamento deste tipo de abordagem no _Dockerfile_ se dará pela seguinte utilização da cláusula _ARG_:

```Dockerfile
#Imagem base do NodeJS
FROM node:alpine3.21

#Identificador opcional
LABEL maintainer="ettory-martins"

#Criação de diretório
RUN mkdir /var/node

#Install curl
RUN apk add curl

#Mudança de diretório pwd
WORKDIR /var/node

#Cópia de arquivo da aplicação para ".", que nesse caso é o WORKDIR
COPY app.js .

#Utilização da cláusula ARG
ARG VERSION

#Definição de valor default (caso não seja informado no build)
ENV VERSION=${VERSION:-1.0.0}

#Executa a aplicação
CMD [ "node", "app.js" ]
```

A etapa de _build_ desta imagem será realizada da seguinte forma (seguindo a injeção da variável de ambiente _VERSION_, com a metodologia de _Build Arguments_):

```bash
docker build --build-arg VERSION=1.1.0 -t nodeapp:0.1 .
```
