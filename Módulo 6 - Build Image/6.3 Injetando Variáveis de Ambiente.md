Para a injeção de variáveis de ambiente no Dockerfile, o código deverá seguir a estrutura de armazenamento de valores em variáveis de ambiente. Segue abaixo um exemplo em uma aplicação simples feita em Javascript:

```javascript
const http = require('http');
const hostname = '0.0.0.0';
const port = process.env.PORT;
const version = process.env.VERSION;
const server = http.createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/plain');
  res.end('Hello World');
});

server.listen(port, hostname, () => {
  console.log(`Server running at http://${hostname}:${port}/ and version ${version}`);
});

process.on('SIGINT', function() {
    process.exit();
});
```

Neste exemplo, as variáveis _version_ e _port_ armazenam seus valores em variáveis de ambiente, que serão fornecidos seus valores posteriormente na execução dos containers baseados na _Docker Image_ gerada no seguinte _Dockerfile_:

```Dockerfile
#Imagem base do NodeJS
FROM node:alpine3.21

#Identificador opcional
LABEL maintainer="ettory-martins"

#Criação de diretório
RUN mkdir /var/node

#Install curl
RUN apk add curl

#Mudança de diretório pwd
WORKDIR /var/node

#Cópia de arquivo da aplicação para ".", que nesse caso é o WORKDIR
COPY app.js .

#Cláusula EXPORT se torna desnecessária

#Executa a aplicação
CMD [ "node", "app.js" ]
```

A forma para execução de containers utilizando múltiplas variáveis de ambiente, como neste caso, se dá pela separação individual de parâmetros _-e_ para suas designações, como no exemplo abaixo:

```bash
docker run -e PORT=5000 -e VERSION=1.0 nodeapp:0.1
```

> É expressamente recomendado que esta seja a abordagem utilizada para a execução de containers, aumentando a segurança e integrações com outras ferramentas como, por exemplo, o _Helm_.
