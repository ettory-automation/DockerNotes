Por padrão, quando o Docker é instalado, este cria automaticamente, uma interface de rede bridge no host chamada _docker0_. **Caso não seja especificado qual interface de rede ou tipo de rede será utilizado pelo container, este irá utilizar o tipo de rede bridge e a interface de rede _docker0_, por padrão.**

Para confirmar isso, podemos executar os seguintes passos abaixo e comparar os resultados:

```shell
ip -c a | grep "docker0"
```

Podemos comparar a saída do comando anterior, com o campo identificado como _"IPAddress": <ip\>_ dentro do bloco denominado _bridge_, no comando a seguir:

```shell
docker inspect <container_id>
```

Caso estes resultados estejam demonstrando a localidade dentro da mesma rede, isto significa que o container está utilizando da interface bridge fornecida por padrão pelo Docker na interface _docker0_, geralmente possuindo sua sub-rede como _172.17.0.0/16_.


## Criando uma bridge interface isolada

Embora o Docker crie, por padrão, uma interface bridge chamada _docker0_, é possível criar outras interfaces bridge isoladas dessa rede padrão. Isso é útil em situações onde se deseja que diferentes grupos de containers (ou aplicações) se comuniquem entre si, mas sem permitir que outros containers de grupos diferentes tenham acesso a essa comunicação. Esse tipo de isolamento é frequentemente necessário para criar redes privadas para grupos de containers que necessitam de segurança ou separação de tráfego de dados.

Outra vantagem na criação de uma bridge interface alheia à _docker0_ padrão, é o fato de que a _docker0_ não possui a capacidade de resolver nomes. Isto pode ser perfeitamente aplicado em outras bridge interfaces.

### Caminhando para a prática:

* Listar opções de comandos para network:

```shell
docker network
```

* Listar networks existentes:

```shell
docker network ls
```

* Criar network:

```shell
docker network create <network_name>
```

* Conectar container a network:

```shell
docker network connect <network_name> <container_name>
```

* Desconectar container de network:

```shell
docker network disconnect <network_name> <container_name>
```

* Adicionar um alias para o container na network:

```shell
docker network connect --alias=<alias_name> <network_name> <container_name>
```

Para testar resolução de nomes gerada pelo parâmetro demonstrado em _\--alias=<alias_name>_, devemos criar um novo container dentro da mesma network, para teste. Pois a resolução de nomes só irá funcionar dentro da mesma bridge network. Então, vamos criar o container na network, e configurar para realizar o teste, com os comandos abaixo:

```bash
docker run --network <network_name> -it alpine sh
```

```bash
apk add curl bind-tools
```

```bash
curl <alias_name>
```

```bash
host <alias_name>
```

Isto atesta que a comunicação entre os containers pela interface bridge foi realizada com sucesso.
